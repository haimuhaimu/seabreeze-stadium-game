# 海风联赛轮次事件设计

## 1. 目的与边界

海风联赛已经具备七轮赛程、人物关系、三项经营行动、永久建设、积分榜和精英资格，但七轮之间主要由玩家主动选择行动驱动，缺少不可回避的外部变化。这个里程碑增加“轮次事件册”，让每一轮都有一件发生在具体人物和具体场地上的现实事件。

本次只增加一个独立子系统：轮次事件。它不引入转会、实时足球、复杂伤病名单或新的地图。事件必须复用现有六位人物、两张地图、经营资源和三段式比赛，增强已有循环，而不是建立另一套菜单游戏。

## 2. 方案选择

考虑过三种方案：

1. 固定七段赛季主线。优点是情绪推进最强，缺点是第二赛季会完全重复。
2. 纯随机事件池。优点是重复游玩变化大，缺点是首赛季缺少清楚的人物弧线。
3. 有顺序的首赛季事件册，后续赛季按固定偏移轮换。首赛季形成从共享场地到精英评审的完整弧线，第二赛季开始改变事件出现顺序，同时保持确定性存档和可测试结果。

采用第三种方案。事件不是随机抽卡，也不会出现无法复现的结果。

## 3. 事件册

首赛季七轮依次出现：

| 轮次 | 事件 | 核心人物 | 现实分歧 |
| --- | --- | --- | --- |
| 1 | 谁先用半块场地 | 小满、郭教练 | 青训孩子和一队训练同时到场 |
| 2 | 暴雨后的排水口 | 林川、许姨 | 用现金抢修，还是请社区一起处理 |
| 3 | 小满说膝盖有点疼 | 小满、郭教练 | 休息、本人决定，或为了比赛继续训练 |
| 4 | 直播合同多了一行字 | 沈峤、罗馆长 | 现金、公开条件和球场控制权冲突 |
| 5 | 工资袋少了一份 | 许姨、林川 | 先补工资、公开缺口，或把钱留给工程 |
| 6 | 客队球迷提前到了 | 罗馆长、林川 | 入口安全、社区接待和主队备战冲突 |
| 7 | 精英评审没有提前通知 | 六位人物 | 用结果证明、公开全部账本，或先让评审看社区时段 |

事件池保留九个位置，另外两个为“集市收摊以后”和“队长该不该有一票”。第 `N` 个赛季从事件池偏移 `(N - 1) × 3` 个位置读取七件事，因此后续赛季顺序变化，但同一存档的结果始终可复现。

## 4. 选择与后果

每件事件提供三个日常语言选择。每个选择包含：

- 一段明确结果文字。
- 对现金、进攻、防守、凝聚、社区、球场状态或治理的精确数值变化。
- 对一至两位人物关系的 `-1`、`0` 或 `+1` 变化，关系仍限制在 0 至 5。
- 一个本轮比赛回响标签，例如进攻、防守、青训、社区、看台、集市、教练或凝聚。

没有一个选项同时在所有维度占优。短期比赛优势可能损害关系，公开程序可能花钱，照顾身体可能减少训练收益。所有选择都能继续赛季，不产生死档。

事件不占用三个经营行动位。玩家可以先训练、建设或谈话，再处理事件，但在事件回应前不能开始本轮比赛。事件选择会写进长期历史，后续赛季仍可查看。

## 5. 状态与接口

新增不可变内容模块 `season-events.js`，导出事件池、`getSeasonEvent(roundIndex, seasonNumber)` 和 `getSeasonEventChoice(eventId, choiceId)`。

赛季状态增加：

```js
week: {
  eventId: null,
  eventChoiceId: null,
  eventTag: null
}
eventHistory: [
  { seasonNumber, round, eventId, choiceId, resultCopy }
]
```

`resolveSeasonEvent(state, eventId, choiceId)` 只处理赛季内部数据：记录选择、更新人物关系、加入本轮回响标签和事件历史。`game-state.js` 的 `chooseSeasonEventDecision` 负责把共享资源效果应用到经济、球队、社区、设施和治理状态。

版本 5 存档保持兼容。`cloneSeasonState` 对缺失的新字段补默认值，因此已有版本 5 联赛存档在下一次状态变化时自动获得事件状态，不需要再次迁移或覆盖原存档。

## 6. 地图与界面

未回应的事件在对应地图显示一个“本轮来信”目标。目标使用现有可行走路线和互动距离检查：办公室适合合同、工资和评审；主场入口适合客队球迷；训练场边线适合青训和身体事件；场边小店适合集市事件。

事件面板使用现有人物全身贴图、浅蓝灰纸张、珊瑚红强调色和一段短对话。它包含事件标题、两至三段事实、三个选择和明确的资源倾向，不使用专业足球术语。

常驻联赛卡在未回应时显示“本轮事件待回应”。联赛手册增加“最近留下的决定”，展示最近三次事件结果。赛后结算增加本轮事件名称和选择，不再只显示行动数。

## 7. 比赛回响

事件选择的标签加入现有 `week.helpTags`，复用比赛回调判断。例如共享半场可提供青训或社区回响，公开直播条款可提供治理或凝聚回响，先照顾伤病可提供理疗室回响。

比赛面板继续只显示三个临场时刻。准备充分时文案显示“本轮那件事会回应这个选择”，玩家可以理解事件和比赛之间的关系，不需要额外数值解释。

## 8. 错误与恢复

- 不认识的事件或选择抛出明确类型错误。
- 同一轮事件只能结算一次。
- 非活动赛季、已完成轮次和已完成赛季不能结算事件。
- 已完成三项行动但未处理事件时，地图只保留事件目标，不显示比赛入口。
- 比赛中断仍只清除比赛本身，事件选择、行动、建设和人物谈话全部保留。
- 旧版本 5 状态缺少事件字段时按“本轮尚未回应、历史为空”处理。

## 9. 验证标准

- 首赛季七轮按表格顺序出现七件不同事件，第二赛季顺序发生确定性变化。
- 每件事件有三个不同选择和完整数值后果，文案没有占位符。
- 事件不占经营行动，但未回应时比赛不能开始。
- 事件能改变共享经营资源、人物关系并产生比赛回响。
- 事件选择跨轮次和跨赛季保留，旧版本 5 联赛存档能继续。
- 所有事件目标停在可互动距离内，桌面和 390 × 844 手机端面板可见且可滚动。
- 浏览器自动流程实际完成一件事件、三项行动、一场比赛，并在下一轮看到事件历史。
