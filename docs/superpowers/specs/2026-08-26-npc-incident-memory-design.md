# NPC 事件记忆设计

## 目标

让海风联赛里的 NPC 记住玩家具体处理过的事件，而不是只显示关系数值。事件的当事人和受影响者会在当轮立即回应，并在下一轮事件发生前继续提起上轮决定。玩家可以进行一次不占经营行动的后续谈话，长期关系因此更依赖实际互动。

## 玩家体验

1. 玩家处理本轮事件后，两个最相关的 NPC 会改口谈论刚刚发生的决定。
2. 即使玩家在事件前已经完成本轮正式谈话，仍可重新靠近这个 NPC，看到新的事件回应。
3. 每轮可与每位有事件记忆的 NPC 进行一次“把这件事谈清楚”。它不占三个经营行动，消耗少量场内时间并使关系增加 1，最高为 5。
4. 进入下一轮而尚未处理新事件时，NPC 会继续记得上一轮的决定。新事件处理后，对话上下文切换到新事件。
5. 没有参与某件事的 NPC 继续使用原有联赛台词，不会全员机械复述同一选择。

## 内容结构

新增独立内容文件 `season-reactions.js`。九个事件的二十七个选择各有两名 NPC 的专属反应，共五十四条短对话。反应以 `eventId -> choiceId -> npcId -> copy` 存储，内容不改变原事件定义，便于独立扩写与测试。

新增纯规则文件 `season-memory.js`，导出：

- `getSeasonNpcMemory(season, npcId)`：返回当前可见的事件记忆，或 `null`。
- 返回值包含事件、选择、NPC、发生轮次、`current` 或 `previous` 时态、可见标签和专属台词。

记忆选择顺序固定：

1. 本轮事件已处理时，只检查本轮事件。
2. 本轮事件未处理时，只检查事件历史中的最后一条。
3. 对应选择没有该 NPC 的专属反应时返回 `null`，不向更早历史无限回溯。

## 状态与兼容

`season.week` 新增 `memoryNpcIds: []`，记录本轮已经完成后续谈话的人。新一轮自动清空。旧版版本 5 存档缺少该字段时，由 `cloneSeasonState` 补为空数组，不提升存档版本。

新增 `recordSeasonMemoryTalk(season, npcId)`：

- 只有 `getSeasonNpcMemory` 返回内容时可调用。
- 同一 NPC 每轮只能完成一次。
- 不写入 `week.actions`。
- 对应 NPC 关系增加 1，并限制在 0 到 5。

共享游戏状态新增 `chooseSeasonNpcMemory(state, npcId)`，负责增加 6 分钟、写入日志并保留其他经营状态。

## 界面

联赛人物对话框在姓名与关系下增加一条记忆来源：

- 当前事件显示“回应刚刚的决定”。
- 上轮事件显示“还记得第 N 轮”。
- 同时显示事件标题和玩家当时的选择。

有可回应记忆且本轮尚未跟进时，提供“把这件事谈清楚”按钮。完成后按钮变成静态记录，但原有三种正式回应仍按原规则独立存在。

## 验证

- 内容测试覆盖二十七个选择均有两名有效 NPC 的非空反应。
- 纯规则测试覆盖当前事件、跨轮记忆、无关人物、新事件覆盖旧事件和第二赛季轮换。
- 状态测试覆盖不消耗行动、关系上限、同轮去重与旧存档补字段。
- 浏览器流程在第一轮处理“谁先用半块场地”后与小满跟进，并在第二轮新事件处理前确认小满仍记得上轮选择。
- 桌面与 390 × 844 手机布局均不溢出，浏览器控制台无错误。
